Kimi K3 논문의 요지는 “파라미터를 3배로 늘렸다”가 아닙니다. 정보가 지나다니는 길을 세 방향으로 뚫었다는 쪽에 가깝습니다. 아래 세 개를 직접 만져보면 대부분 이해됩니다.

2.78T전체 파라미터 (K2는 1.04T)
104B토큰 하나당 실제로 켜지는 양
2.5×같은 연산으로 뽑는 성능 (자체 측정)

먼저 이것만

모르는 게 정상입니다

논문에 나오는 이름들 — KDA, AttnRes, LatentMoE, SiTU-GLU — 은 새로 지어낸 상표명입니다. 이름을 외울 필요는 전혀 없고, 각각이 어떤 막힘을 뚫으려고 만들어졌는지만 알면 됩니다.

세 개의 막힘이 있습니다. 아래 세 칸이 그것입니다.

→가로 · 글이 길어지면 느려진다
↓세로 · 층이 깊어지면 흐려진다
◇폭 · 넓히면 비싸진다

막힘 1 / 3

→가로 · 시퀀스 길이

글이 길어지면 왜 느려지나

기존 방식(어텐션)은 새 단어 하나를 읽을 때마다 앞의 모든 단어를 처음부터 다시 훑습니다. 그래서 글이 2배 길어지면 비용은 4배가 됩니다. 100만 토큰에서는 이 방식이 감당이 안 됩니다.

K3가 주로 쓰는 방식(KDA)은 대신 요약 노트 한 장을 계속 고쳐 씁니다. 노트 크기는 고정이라, 글이 2배 길어져도 비용은 2배만 됩니다.

기존 어텐션 비용1×
KDA 비용1×

그럼 왜 전부 KDA로 안 하나? 요약 노트는 싸지만 원본만큼 정확하지 않습니다. 그래서 K3는 KDA 3층마다 원본을 전부 다시 보는 층(MLA)을 1층씩 끼워 넣습니다. 전체 93층 중 KDA 69층 + MLA 24층이고, 맨 마지막 층은 반드시 MLA입니다.

막힘 2 / 3

↓세로 · 네트워크 깊이

층이 깊어지면 왜 흐려지나

신경망은 층을 차례로 통과합니다. 기존 방식에서 93번째 층이 3번째 층의 정보를 보려면 그 사이 90개 층을 전부 거쳐야 합니다. 전언 게임처럼 뒤로 갈수록 초기 정보가 흐려집니다.

AttnRes는 먼 층을 직접 건너다보게 만듭니다. 게다가 어느 층을 얼마나 볼지 매번 스스로 정합니다.

현재 보는 층 12층
정보가 선명하게 도착 거치면서 흐려짐

실제 K3는 93개 층을 12층짜리 8블록으로 묶고, 블록끼리만 건너다보게 했습니다. 모든 층을 전부 연결하면 메모리가 감당이 안 되기 때문입니다.

막힘 3 / 3

◇폭 · 모델 너비

넓히면 왜 비싸지나

지식을 늘리려면 모델을 넓혀야 하는데, 넓힌 만큼 전부 계산하면 감당이 안 됩니다. 그래서 작은 전문가를 잔뜩 두고 매번 몇 명만 부르는 방식(MoE)을 씁니다.

K3는 층마다 전문가를 896명 두고, 토큰 하나를 처리할 때 그중 16명만 켭니다. 아래 버튼을 눌러보세요.

켜진 전문가 0 / 896
이번 토큰에 켜진 전문가 대기 중

버튼을 눌러 몇 명이나 켜지는지 보세요.

여기서 진짜 문제는 “누구를 부를까”입니다. 896명 중 인기 있는 몇 명에게만 일이 몰리면, 그 사람은 과부하로 느려지고 나머지는 불려본 적이 없어서 실력이 안 늡니다. K3의 Quantile Balancing은 “상위 몇 %”라는 상대평가 방식으로 매번 컷을 다시 그어서 일감을 고르게 나눕니다.

보너스 · 가장 실용적인 아이디어

숫자가 너무 커지면 터진다

모델을 싸게 돌리려면 숫자를 아주 적은 비트로 저장해야 합니다. K3는 4비트(MXFP4)를 씁니다. 문제는 4비트로 표현할 수 있는 숫자 범위가 좁다는 것 — 계산 도중 값이 너무 커지면 그냥 넘쳐버립니다.

기존 표준 부품(SwiGLU)은 값에 상한이 없습니다. K3는 부드러운 뚜껑을 씌운 부품(SiTU-GLU)으로 바꿨습니다. 정상 범위에서는 원래와 거의 똑같이 동작하고, 극단에서만 뚜껑이 작동합니다.

SwiGLU 출력 (기존)—
SiTU-GLU 출력 (K3)—

같은 발상이 논문 곳곳에 반복됩니다. 수식의 형태를 살짝 바꿔서 하드웨어가 싫어하는 상황 자체를 없앤다. 논문에서 “알고리즘–시스템 공동설계”라고 부르는 게 이겁니다. 이 논문의 진짜 성격을 한 줄로 말하면, 새로운 지능 이론이 아니라 공학적 병목 제거의 모음집에 가깝습니다.

세 문장 요약

1. K3는 파라미터를 2.8조로 늘렸지만, 논문의 주장은 크기가 아니라 정보가 지나가는 길을 가로·세로·폭 세 방향으로 뚫었다는 것입니다.

2. 개별 기법들은 대부분 “하드웨어가 싫어하는 상황을 수식 차원에서 없앤다”는 같은 발상의 변주입니다 — 값에 뚜껑 씌우기, 예외 처리 경로 없애기, 일감 고르게 나누기.

3. 결과적으로 최상위 상용 모델(Claude Fable 5, GPT-5.6 Sol)에는 아직 못 미치지만, 비슷한 성능을 절반 이하 비용으로 내면서 가중치를 전부 공개했다는 게 이 발표의 의미입니다.

비판적으로 볼 지점 하나. 핵심 수치인 “2.5배”는 아키텍처·데이터·학습 레시피 개선을 전부 합친 결과입니다. 어느 기법이 얼마나 기여했는지는 이 보고서만으로는 분리되지 않습니다.
